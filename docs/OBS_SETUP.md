# OBS セットアップ

## 0. アプリの起動と終了

インストーラー版は初回起動後、Windowsログイン時に画面を出さずOBSドック用サーバーを準備します。Windows側の自動起動が遅れた場合は、同梱OBSプラグインがインストール済みアプリをバックグラウンドで起動します。利用者がNode.jsやローカルサーバーを別途インストール・起動する必要はありません。Portable版は自動起動へ登録しないため、OBSより先にPortable EXEを起動します。

デスクトップ画面の×は通知領域への格納です。`http://127.0.0.1:4317` のドックを維持するため、サーバーは動作を続けます。EXEの再実行または通知領域の「開く」で画面を戻せます。「完全に終了」を選んだ場合だけサーバーも停止し、OBSドックは接続できなくなります。

## 1. 事前バックアップ

初回作業前に OBS の「プロファイル」と「シーンコレクション」をエクスポートし、OBS 設定ディレクトリと Stream Deck プロファイルを別の場所へコピーしてください。本アプリはOBSが停止している時だけ、内蔵接続設定、`Stream Manager`ドック、選択中プロファイルのFHD 60 FPS／YouTube CBR 10000 kbps／Twitch CBR 6000 kbps／A1〜A5録画設定を安全に追加します。既存の他のドック、保存先、エンコーダー種別などは維持し、OBS起動中は設定ファイルを書き換えません。

## 2. プロファイルとシーン

OBS プロファイルを `MAIN_YOUTUBE_TWITCH`、シーンコレクションを `STREAM_MAIN` とし、次のシーンを作成します。

```text
00_STARTING
10_GAME_PC
11_GAME_SWITCH
20_TALK
30_AWAY
40_TECHNICAL_DIFFICULTIES
90_ENDING
```

ゲームごとにシーンや OBS プロファイルを複製しないでください。ゲーム差分は本アプリのゲームプロファイルに保存します。

## 3. ソース名

アプリの初期値は次の名前を参照します。既存ソース名を使う場合はアプリの設定とゲームプロファイル側を変更します。

```text
映像: PC Game Capture / GFN Capture / PC Window Capture / Elgato Game Capture
音声: MIC / GAME_PC / GAME_GFN / GAME_SWITCH / DISCORD / BGM / ALERT
```

`10_GAME_PC` には PC、GFN、予備ウィンドウのキャプチャを配置します。`11_GAME_SWITCH` には Elgato の映像・音声を配置します。ゲーム選択時に対象キャプチャだけが有効になります。

ゲーム選択時、PC/GFNのゲーム音は映像用Game/Window Captureのアプリ音声機能を自動で有効化して取得します。`DISCORD`がデバイス全体の音声出力キャプチャだった場合は、元ソースをミュート状態で退避し、`Discord.exe`だけを取得するOBS標準のアプリケーション音声キャプチャへ自動移行します。移行に失敗した場合は元ソース名・ミュート・トラック設定を復元します。デバイス全体を掴む旧`GAME_*` / `BGM`ソースは、ゲーム音の二重収録と長時間の音声バッファ遅延を防ぐため録画・配信MIXから外します。BGMストックは管理用メディアソースからA4へ直接送ります。

## 4. OBS接続（通常は操作不要）

内蔵接続機能、ローカルパスワード、ブラウザドックはアプリが自動設定します。初回画面が再起動を案内した場合だけOBSを一度終了し、再度起動してください。手動復旧が必要な場合に限り、アプリの「設定」→「OBS連携」→「高度な接続設定」を開きます。

## 5. 音声

ゲームを選択してOBSへ適用した後、ゲーム設定の「音声」から「開始してゲームへ戻る」を実行します。設定画面は自動で退避するため、ゲームへ戻って普段の声量で話してください。ゲーム音も取得できればマイクとの相対差まで、取得できなければゲーム音量を変えずマイクだけを15秒測定して調整します。DiscordとBGMも鳴っていれば同時に調整します。

自動調整は実音量を三段階で測定し、ゲーム別の音量を保存します。マイクには次の管理フィルターを自動作成します。

1. ゲーム別の追加ゲイン（0〜+30 dB、リミッター前）
2. RNNoise ノイズ抑制
3. エキスパンダー（2:1、-45 dB）
4. 小さい発話を持ち上げるアップワードコンプレッサー
5. コンプレッサー（3:1、+6 dBメイクアップ）
6. リミッター（ピーク保護）

ゲーム音には、マイクをサイドチェイン入力にしたコンプレッサーとリミッターを追加し、発話中に既定で約6 dB下がるよう調整します。声質に依存するEQは自動作成しません。

既存のカスタムフィルターは無条件に上書きしません。測定条件、目標値、ロールバック動作は [AUDIO_AUTO_ADJUST.md](AUDIO_AUTO_ADJUST.md) を参照してください。

```text
Track 1: ゲーム音
Track 2: Discord
Track 3: マイク
Track 4: BGM
Track 5: キャプチャ内蔵音声 / AUX
Track 6: YouTube・Twitch配信用フルMIX
```

OBSが基本出力モードだった場合は、OBS停止中に詳細出力モードへ自動変更します。現在読み込まれている出力機構が切り替わるまでは、分離されていない録画や不安定な配信を開始しません。

## 6. 録画とプラグイン

- OBS 録画形式は MKV にします。
- 通常録画とリプレイは配信と同じ映像エンコーダーを共有し、解像度やFPSを下げずに余分なエンコードを増やさない構成にします。
- リプレイバッファを有効にします。秒数はゲーム選択時にアプリが更新します。
- OBS Stream Manager Output は配布物に同梱され、アプリ起動時にOBS公式のWindows用プラグイン領域`C:\ProgramData\obs-studio\plugins`へ自動配置されます。初回または更新後はOBSを再起動してください。
- Aitum Vertical は 1080×1920 の録画を作ります。アプリは Aitum Vertical の公式 WebSocket vendor request で縦録画を開始・停止します。

Aitum Verticalが未導入、無効、またはvendor request非対応の場合は警告を表示し、縦録画だけをスキップします。

Source Recordは個別出力のフレーム落ちを監視できないため、配信中は開始しません。Aitum Verticalは新規設定では既定OFFです。YouTube・Twitch同時配信では、FHD 60 FPSの両配信とA1〜A5分離録画を守るため縦録画を開始しません。主配信エンコーダーはYouTube向けCBR 10000 kbps、Twitch専用エンコーダーはCBR 6000 kbps、どちらもキーフレーム2秒、Bフレーム2、NVENC look-ahead無効へ開始前に固定し、録画は主配信エンコーダーを再利用します。画質、配信解像度、FPSを下げる回避は行いません。

Twitch配信キーはOAuthで取得してWindows資格情報へ保存し、配信開始時だけOBS Stream Manager Outputへ渡します。通常設定、Aitum設定、ログ、バックアップには保存しません。設定画面の「映像・録画負荷をテスト」は`bandwidthtest=true`で主配信、Twitch副出力、通常録画、リプレイを15秒間同時に動かし、実測FPSとエンコード欠落を確認します。視聴者には公開されません。通常配信時は実配信状態表示でTwitchが`LIVE`になったことを確認してください。

### ゲーム別録画専用モード

配信モードを置き換えず、選択中のゲームに対して「録画のみ」を追加します。専用OBSプロファイル`OBS Stream Manager - Recording 1440p`へ一時的に切り替え、2560×1440/60 FPS、NVENC H.264、VBR 平均8 Mbps／上限10 Mbps、P5、シングルパス、Look-ahead OFF、Adaptive Quantization OFF、MKV、48 kHz、A1〜A6分離を固定します。容量目安は6音声込みで1時間約4 GB、上限付近では約5 GBです。録画ファイルと自動リマックス後のMP4には選択中のゲーム名が付き、未指定時の保存先もゲーム別フォルダーになります。録画停止後は元のOBSプロファイルへ戻ります。

この経路はYouTube／Twitchの配信枠、RTMP、コメントを操作しません。Steamバックグラウンド録画はOFFにし、VOCALOID、MikuMikuDance、字幕・主要編集ソフトは録画中に同時起動しません。初回は対象ゲームを10分プレイし、次を確認します。

- 録画ファイルを実際に再生し、目視でカクつきや静止に近い区間がない
- 録画中の1% Lowが録画なしの同条件より5%以上悪化していない
- 1440p60の時間軸、映像フレーム、A1〜A6音声トラックに欠落がない

上記を満たさない場合だけ、ER330Gの1080p60 NAS直接保存へ切り替えます。

## 7. Advanced Scene Switcher

次のマクロを作成します。

- 配信中にゲーム映像が一定時間非アクティブ → `40_TECHNICAL_DIFFICULTIES`
- ローカルゲームまたは GFN が終了 → `30_AWAY`、ゲーム音ミュート
- 配信開始後に MIC が一定時間完全無音 → 警告
- 映像復帰 → 元のゲームシーン

本番前に各条件を意図的に発生させ、安全画面へ切り替わることを確認してください。

## 8. 共通配信テンプレート

ゲームごとに背景画像を作り直さず、共通画面の文字だけを差し替える場合は次のように準備します。

1. 共通画面を表示したいシーンに画像ソースを追加します。
2. 画像ソース名を既定の `COMMON_STREAM_TEMPLATE` にします。別名を使う場合はアプリ設定と同じ名前に揃えます。
3. アプリの「設定」→「共通配信テンプレート」でPNG、JPG、またはWEBPを登録します。
4. 表示文字へ `{game}` を入れ、位置、フォント、色、縁取りを調整します。
5. ゲーム名を短く表示したい場合は、そのゲームの設定で「テンプレート表示名」を指定します。
6. 「全プロファイルで有効」をオンにして保存します。

保存時に全ゲーム分のPNGが生成されます。以後はゲームを選ぶたびに、そのプロファイル用PNGがOBS画像ソースへ自動設定されます。画像ソースが見つからない場合はゲーム選択自体を止めず、警告として表示します。

## 9. 本番前チェック

- YouTube を限定公開にして配信枠、タイトル、サムネイルを確認
- Twitch のタイトル、カテゴリ、タグを確認
- YouTube / Twitch コメントがドックへ表示されることを確認
- PC、GFN、Switch、VALORANT、Roblox の各キャプチャを確認
- マイク無音、ゲーム映像消失、片方の配信失敗を確認
- 通常録画、A1〜A5の音声、Vertical、リプレイ保存を確認
- OBS 統計で描画遅延、エンコード遅延、ネットワークドロップを確認
